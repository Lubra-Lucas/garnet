# Solicitação para criação do aplicativo **GARNET**

## 1. Stack e Execução

• **Linguagem:** Python 3.11+

• **Interface:** Streamlit multipage (pasta `pages/`)

• **Banco de dados (dev):** SQLite em `data/app.db`

• **Banco de dados (prod):** PostgreSQL via variável `DATABASE_URL` (fallback para SQLite)

• **ORM/validação:** SQLModel (com SQLAlchemy) + Pydantic

• **Autenticação/RBAC:** login com `passlib[bcrypt]`; perfis iniciais: `manager`, `operator`, `viewer` (expansível para Admin/PCP/Qualidade/Compras/Financeiro/Estoque/Vendas)

• **Cache:** `st.cache_resource` (conexão DB) e `st.cache_data` (relatórios)

• **Uploads/Exportação:** `openpyxl` (Excel), `pandas` (CSV/XLSX), geração de PDF opcional (`reportlab`)

• **Dependências:**

* streamlit
* sqlmodel
* sqlalchemy
* pydantic
* passlib\[bcrypt]
* pandas
* numpy
* plotly
* python-dotenv
* psycopg2-binary
* openpyxl
* reportlab (opcional para PDFs)

• **Execução (desenvolvimento):**

```bash
streamlit run app.py --server.port $PORT --server.address 0.0.0.0
```

(Em Windows PowerShell, use `$env:PORT=8501` antes, se necessário.)

• **Variáveis de ambiente (.env):**

```
DATABASE_URL=postgresql+psycopg2://usuario:senha@host:5432/database
SECRET_KEY=troque_esta_chave
APP_ENV=dev
```

## 2. Banco de Dados

Criar `db.py` com suporte automático a SQLite/Postgres:

```python
# db.py
import os
from sqlmodel import SQLModel, create_engine

DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///data/app.db")
connect_args = {"check_same_thread": False} if DATABASE_URL.startswith("sqlite") else {}
engine = create_engine(DATABASE_URL, echo=False, connect_args=connect_args)

def init_db():
    SQLModel.metadata.create_all(engine)
```

• No deploy, definir `DATABASE_URL` no formato `postgresql+psycopg2://usuario:senha@host:5432/database`.

• **Seeds/Import:** comando inicial em `services/business.py` para importar cadastros a partir de planilhas (Fornecedores, MPs, Produtos, Planilha Payot, Análise Pagamentos, Planilha Produção).

## 4. Autenticação e Sessão

• Tela inicial com **login (usuário/senha)**.

• Usuário logado fica em `st.session_state["user"] = {id, name, role}`.

• Páginas verificam `role` para permitir/recusar ações (RBAC básico).

• Perfis futuros: Admin, PCP, Qualidade, Compras, Financeiro, Estoque, Vendas/Atendimento.

**`auth.py` (esqueleto):**

```python
# auth.py
import streamlit as st
from passlib.context import CryptContext
from sqlmodel import Session, select
from models import User
from db import engine

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def hash_password(password: str) -> str:
    return pwd_context.hash(password)

def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)

def login_form():
    st.title("GARNET – Login")
    u = st.text_input("Usuário")
    p = st.text_input("Senha", type="password")
    if st.button("Entrar", use_container_width=True):
        with Session(engine) as s:
            user = s.exec(select(User).where(User.username == u)).first()
            if user and verify_password(p, user.password_hash):
                st.session_state["user"] = {"id": user.id, "name": user.name, "role": user.role}
                st.success("Autenticado!")
                st.experimental_rerun()
            else:
                st.error("Usuário ou senha inválidos.")

def require_login(roles: list[str] | None = None):
    user = st.session_state.get("user")
    if not user:
        st.stop()
    if roles and user.get("role") not in roles:
        st.error("Acesso negado para seu perfil.")
        st.stop()
```

**`app.py` (gate + Home):**

```python
# app.py
import streamlit as st
```

```python
    category: str | None = None

class FormulaItem(SQLModel, table=True):

    uom: str
    percent: float | None = None

class StockLot(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    item_type: str  # MP ou PA
    item_id: int
    lot_code: str
    qty: float
    uom: str
    expiry: date | None = None
    status: str = Field(default="Aprovado")
    avg_cost: float | None = None
    location: str | None = None

class ProductionOrder(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    code: str = Field(index=True, unique=True)
    product_id: int = Field(foreign_key="product.id")
    qty_to_produce: float
    planned_lot: str | None = None
    start_date: date | None = None
    end_date: date | None = None
    workcenter: str | None = None
    status: str = Field(default="Planejada")

class PurchaseOrder(SQLModel, table=True):
```

## 6. Serviços (Regras de Negócio)

**`services/business.py` (esqueleto):**

```python
# services/business.py
from sqlmodel import Session, select
from models import RawMaterial, Product, Formulation, FormulaItem

# Custo proporcional da MP na formulação (conversões simples)
def material_cost_unit(rm: RawMaterial, qty: float, uom: str) -> float:
    # normaliza para unidade base simples (ex.: G->KG, ML->L)
    factor = 1.0
    if rm.base_unit == "KG" and uom.upper() in ["G", "GRAMAS"]:
        factor = 1/1000
    if rm.base_unit == "L" and uom.upper() == "ML":
        factor = 1/1000
    # se densidade for necessária para conversões massa/volume, aplicar aqui
    return rm.base_price * (qty * factor)

# Custo total do lote + custo por unidade produzida
def formulation_cost(session: Session, formulation_id: int, unit_qty: float) -> tuple[float, float]:
    items = session.exec(select(FormulaItem).where(FormulaItem.formulation_id==formulation_id)).all()
    total = 0.0
    for it in items:
        rm = session.get(RawMaterial, it.raw_material_id)
        total += material_cost_unit(rm, it.qty, it.uom)
    # custo por unidade = total do lote / quantidade usada em 1 produto
    unit_cost = total / unit_qty if unit_qty else 0.0
    return total, unit_cost

# FEFO: ordena lotes por validade crescente para reservas

def fefo_pick(lots):
    return sorted(lots, key=lambda x: (x.expiry or x.id))

# MRP simplificado: Necessidade líquida = demanda - (estoque disponível - reservas)
```

## 8. Funcionalidades por Página

### **Primeira página: Home**

O que irá conter:
• Cards‑resumo: MPs mais consumidas, MPs em estoque, OPs deste mês, Itens com validades próximas, Itens com estoques baixos, Pedidos em andamento.
• Gráfico rápido de consumo por família de MP (últimos 30/90 dias).
• Lista de alertas (ex.: vencimentos, estoques mínimos, OPs atrasadas).
• Barra de pesquisa global (MP, Produto, OP, Fornecedor, Lote).
• Acesso rápido a ações: Criar OP, Cadastrar MP, Cadastrar Produto, Novo Pedido de Compra.

### **Segunda página: Fornecedores**

O que irá conter:
• Tabela de fornecedores com filtros (Nome, CNPJ, Status, Categoria, Avaliação).
• Aba **Cadastrar novo fornecedor**: Nome do Fornecedor, CNPJ, Telefone, Email, Contatos, Endereço, Condição de Pagamento padrão, Prazo médio de entrega, Certificações/ANVISA, Observações.
• Botão **Importar/Exportar** (CSV/Excel).
• Histórico de desempenho (OTD, qualidade, não conformidades).
• Acesso à **Agenda/CRM** (ver página 12).

### **Terceira página: Matérias Primas**

O que irá conter:
• Tabela de MPs: Código, Nome usual, Nome químico, Fornecedor principal, Unidade Base (KG, G, L, ML, UN), Preço por unidade base, Estoque atual, Estoque mínimo, Validade padrão, Localização, Status.
• **Cadastrar nova MP**: Nome Usual, Nome Químico, Fornecedor, Unidade Base, Preço por Unidade Base, Densidade (opcional), Fator de conversão (KG↔G), Descrição técnica/Boletim, Anexos (FISPQ, especificação).
• Ações em massa: Atualizar preços, Definir estoque mínimo, Inativar.

### **Quarta página: Produtos**

O que irá conter:
• Tabela: Código, Nome, Cliente, Categoria/Linha, Custo de Produção (último), Preço Sugerido (Planilha Payot), Status, Peso/Volume unitário, EAN/Interno.
• **Cadastrar novo produto**: Nome, Cliente, Peso/Volume unitário, Rendimento por lote padrão (ex.: 1,5 kg), Impostos/Markup padrão.
• Ao clicar: Formulação associada, ficha técnica, POPs, histórico de custos e OPs.

### **Quinta página: Formulação**

O que irá conter:
• Selecionar Produto e versão.
• Itens: MP, Quantidade por lote padrão (ex.: 1,5 kg), Unidade, %, Custo unitário da MP, Custo proporcional.
• **Cálculo automático:** se MP custa R\$ X por unidade base, e usa‑se q (convertida para a base), custo = `X × (q / unidade_base)`.
• Exibir **Custo total do lote** e **custo de 1 unidade** = (Custo total do lote) ÷ (quantidade usada em 1 produto).
• Campo **Quantidade usada em 1 produto** (ex.: 50 g).
• Controle de versões: Rascunho, Aprovada, Obsoleta.
• Ações: Duplicar, Comparar versões, Exportar ficha (PDF/Excel).

### **Sexta página: Estoque**

O que irá conter:
• Tabela de estoques (MPs e PAs): Item, Lote, Quantidade, Unidade, Vencimento, Status (Aprovado/Quarentena/Reprovado), Custo médio, Localização.
• **Buscar** por nome/código/lote.
• Indicadores: Cobertura de estoque (dias), Itens com validades próximas (FEFO), Itens abaixo do mínimo.
• Movimentações: Entrada, Saída, Transferência, Ajuste (com motivo e anexo).
• Rotinas: Inventário cíclico, Inventário geral, Conferência por código de barras/QR.

### **Sétima página: Ordens de Produção (OP)**

O que irá conter:
• Criar/listar OPs: Código OP, Produto, Qtd a produzir, Lote previsto, Data início/fim, Centro de trabalho, Status (Planejada, Liberada, Em Produção, Concluída, Cancelada).
• **Explosão de MP** a partir da formulação + reserva/baixa de MP (FEFO).
• Apontamentos: início/fim de etapas, consumo real, produção boa/refugo, paradas.
• Anexos: POPs, instruções, checklists.

### **Oitava página: MRP & Planejamento**

O que irá conter:
• MRP simplificado: necessidade de MPs a partir das OPs e previsões.
• **PMP** mensal/semanal, considerando capacidade por turno.
• Sugestões de reprogramação (FIFO/FEFO, lote econômico, sequenciamento por setup).
• Dashboard: carga vs. capacidade, gargalos, OTIF.

### **Nona página: Compras / Pedidos**

O que irá conter:
• Solicitações e pedidos de compra (MP/embalagem/serviços).
• Campos: Fornecedor, Item, Qtd, Preço negociado, Prazo, Condição de pagamento, Status.

### **Décima página: Recebimento & Qualidade**

O que irá conter:
• Pré‑agendamento e registro de recebimento por pedido.
• Criação de **lote de MP** com validade, COA, anexos.

O que irá conter:

• `init_db()` é executado no `app.py` (garante criação de tabelas).
• Para Postgres em produção, configurar `DATABASE_URL` e manter backup do SQLite dev.
• Manter scripts de **importação** para migrar dados das planilhas atuais para o banco.
• Definir **unidades padrão** (G/ML/KG/L/UN) e **conversões** na configuração geral.
